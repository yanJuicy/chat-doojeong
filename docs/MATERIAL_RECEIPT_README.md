# 자재입출고 자동 반영 기능 — 통합 안내

거래처 주문서(구매입고 export .doc — 실제로는 HTML)를 올리면, 자재입출고.xlsx의 "구입" 시트
해당 날짜·품번 행의 "수량" 셀을 자동으로 채워주는 기능입니다.

## 왜 이렇게 만들었는지

`자재입출고.xlsx`의 "구입" 시트는 손으로 입력하는 칸이 **날짜별 "수량" 셀 하나뿐**이고,
나머지(일별 금액, 주간 합계, 월 합계, 총계)는 전부 그 값에서 자동 계산되는 **수식**입니다.
그래서 이 기능은 "수량 셀을 정확히 찾아서 채우는 것"에만 집중하고, 합계·수식은 건드리지
않습니다 — 엑셀이 열릴 때 알아서 재계산됩니다.

## 실제 검증한 내용

받은 샘플 3개(Doc.doc, Doc__1_.doc, Doc__2_.doc) 전부 파싱·매칭·반영까지 실제로 돌려서 확인함:
- 품목 11건 전부 품번(품목코드) 기준으로 시트의 정확한 행을 찾음 (거래처명도 일치 확인)
- 같은 품목을 두 번 반영하면 값이 **누적**됨(덮어쓰기 아님) — 하루에 여러 건 입고되는 상황 고려
- 수량 셀만 수정 후 LibreOffice로 재계산 검증 → 금액 수식·주간합계·월합계 수식 전부 정상 작동 확인

## 알고 계셔야 할 제약 (설계상 의도적으로 안 만든 부분)

1. **신규 품목은 자동으로 행을 만들지 않습니다.** 품번이 시트에 없으면 "미매칭 품목"으로
   목록만 보여주고, 실제 행 삽입은 사람이 하도록 했습니다 — 이 시트는 한 행에 딸린 수식이
   많아서, 자동으로 행을 잘못 삽입하면 다른 행 참조가 깨질 위험이 있다고 판단했습니다.
2. **주문서 작성일의 월과 시트 제목의 월이 일치해야 합니다.** (예: 8월 주문서는 "2026년
   08월" 시트에만 반영 가능) 다르면 명확한 에러 메시지와 함께 반영을 거부합니다 —
   실제로 지금 받은 샘플 파일(자재입출고.xlsx, "2026년 07월")과 주문서 3건(전부 8월 19일)은
   이 이유로 그대로는 반영이 안 됩니다. **8월 시트 파일을 받으시면 그걸로 테스트해주세요.**
3. **"구입"(입고) 시트만 다룹니다.** 받은 파일에 "출고" 시트는 없어서, 출고 자동화는
   범위에서 뺐습니다. 나중에 출고용 시트 양식을 받으면 같은 방식으로 확장 가능합니다.
4. **단가(외부 파일 참조)는 이 코드가 채우는 값이 아닙니다.** 단가 셀 자체가 원래도
   `[1]자전재!...` 형태로 다른 엑셀 파일을 참조하고 있어서, 그 파일이 연결된 실제 업무
   PC에서 열어야 금액까지 정상적으로 계산됩니다.

## 통합 방법

```
app/services/material_receipt/order_parser.py   → 그대로 복사
app/services/material_receipt/xlsx_updater.py    → 그대로 복사
app/reports/material_receipt/router.py            → 복사 후 app/main.py에 등록
frontend/src/components/materialReceipt/MaterialReceiptPanel.jsx → 복사 후 원하는 화면에 배치
```

`app/main.py`에 기존 daily_report/weekly_report 라우터를 등록한 곳 옆에 한 줄 추가:
```python
from app.reports.material_receipt.router import router as material_receipt_router
app.include_router(material_receipt_router)
```

프론트엔드는 기존 `LeftRail.jsx`/`App.jsx`에 다른 Drawer 패널을 연결했던 것과 같은 방식으로
`MaterialReceiptPanel.jsx`를 원하는 위치에 붙이면 됩니다. (className은 예시로 Tailwind
기본 클래스를 썼으니, 프로젝트 디자인 토큰에 맞게 조정 필요)

## 남은 것 — 팀과 확인하면 좋을 것

- 신규 품목이 나왔을 때 "미매칭 목록"만 보여줄지, 아니면 행 자동 추가 기능까지 만들지
- 여러 거래처가 같은 날 같은 품목을 각각 보내는 경우가 실제로 있는지(있다면 지금의
  "누적" 방식이 맞는지, 재확인 필요)
- 최종 저장 위치 — 지금은 사용자가 업로드한 xlsx를 수정해서 그대로 다운로드하게 했는데,
  회사 공용 드라이브의 특정 경로에 자동 저장하길 원하면 그 부분만 추가하면 됨
