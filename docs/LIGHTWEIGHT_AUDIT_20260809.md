## 질문 경로에서 줄인 비용

검색 결과의 파일명은 이미 Qdrant payload에 저장된다. 기존에는 최종 후보마다 PostgreSQL에서 같은 문서 정보를 다시 읽었지만, 이제 payload의 파일명을 먼저 사용한다. 구형 벡터처럼 파일명이 없는 결과만 PostgreSQL에서 보충하므로 하위 호환성은 유지한다.

실측 A/B 결과에 따라 1차 Qdrant 후보를 100→64, 교차인코더 후보를 48→24로 줄였다. 정답 지표는 그대로 유지됐고 최종 반복 측정에서 문서 검색 평균은 약 0.155초→0.087초, 리랭킹 평균은 1.462초→0.628초로 줄었다.

## 유지한 기능과 이유

- dense+sparse 검색, 라벨 검색, RRF 융합, 리랭킹, floor 안전 구조: 16문항 품질에 직접 관여함
- retrieval trace: 일반 채팅에는 노출되지 않고 실패 단계 진단에 필요함
- 의도분류: 검색 순위에는 사용하지 않지만 UI가 전체 유사도를 표시함. 기존 측정 비용도 약 0.14초로 작음
- 질문 캐시: 동일 질문의 전체 검색·LLM 생성을 생략함
- 채팅 로그: 현재 앱에서 조회하지는 않지만 운영·감사 기록일 수 있어 정책 확인 전 보존
- 웹 크롤링·텍스트 수집·재추출 API: 화면 호출만으로 판단하지 않고 문서화된 외부 API라 보존
- PDF 이미지 캡셔닝: 기본값은 꺼져 있지만 스캔·도면 자료 보강 용도로 필요함
- OCR 페이지 캐시와 품질 게이트: 재처리 시간과 깨진 OCR 차단에 직접 필요함
